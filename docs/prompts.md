# 可直接复制的任务话术

按当前阶段选一段，加上自己的参考文件、素材和目标。提示词帮助交接，不替代对实际素材的检查。无需一口气执行所有任务。

## 1. 读取仓库，开始一个项目

```text
请先读取这个仓库的 README.md 和 skills.json。
根据当前任务加载 social-video-design 与 social-video-rebuild，
只读本阶段需要的 references。

我的主题/产品：填写自己的内容。
已有素材：说明参考片、图片、视频或已有工程。
本次范围：先做一个镜头，不制作整条。
交付要求：画幅、时长目标、需要哪些格式。

先说明你看到了哪些文件、还缺什么，已有信息不要反复问。
```

## 2. 拆参考，输出HTML

```text
请先分析参考片，不开始制作。
记录目标段的起止时间、关键截图、主体动作、构图、运镜、速度变化。
拆出进入、稳定、操作、变化、结果、退出的状态。
把观察事实、实现推断、我自己的新方案分开。

输出可交互HTML：目录、截图放大、时间点、素材需求、代码任务。
截图能复制或下载，浏览器受限时提供回退。
不确定原字体或软件时注明，不把推测当事实。
```

## 3. 为自己的产品策划同类片子

```text
请用 social-video-design，把我的一个核心功能变成可见的画面关系。
先给两个不同的开场思路，每个说明第一眼画面、留下的兴趣点、
如何接回产品，再推荐一个适合现有素材的方向。

每镜写观看任务、主体与文案、图形解释什么、结果在哪里。
保留自己的品牌和素材，不照搬参考字标、角色或宣传承诺。
如果是概念演示，明确标注，不冒充产品真实功能。
```

## 4. 生成素材之前

```text
请根据后期目标列素材清单，再给图片与视频提示词。
纯环境图不要包含我准备单独制作的主角；
角色图说明角度、全身/特写与清晰度；
真正视频首帧按镜头开场景别单独考虑。

视频写总时长目标、动作分段、机位、运镜、速度和光照。
不要让生成模型烙入精确文字、参数条、软件窗口或选框。
提前考虑放大、移走主体、局部替换与独立调速的需要。
```

## 5. 检查收到的素材能不能用

```text
请比较我上传的几个视频，不按文件名猜内容。
在开头、中间、结尾检查机位、主体运动、背景与时序一致性。
说明哪些适合直接局部合成，哪些需要对齐，哪些偏差过大。
估计主体放到目标尺寸后是否清晰，是否有足够动作覆盖。
先给实际观察与可行方案，不急着渲染整段。
```

## 6. 做稳定关键帧

```text
先用我的素材摆出这一镜的核心稳定状态。
给出主体、标题、正文和控件的相对位置、层级与安全区域。
更换文案后重新排版，不把长字硬缩得很小。
控件明确是贴屏幕、跟对象还是贴物体表面。
我先看关键帧，再连接进入、变化和退出。
```

## 7. 制作窗口或图层展开

```text
请按参考关系用代码重建窗口/图层，不拿原片截图盖上来。
每一层的内容与外框共用变换，保留前后遮挡。
指定谁先退出、谁后退出、形变方向与标题露出点。
展开后检查空位背景、主体边缘和阴影；
把关键时刻排成连续截图，让我看状态衔接。
```

## 8. 局部换字或换贴纸

```text
我有同一基础运动的旧状态、空白状态、新状态。
先对齐时间和画面，不切换整帧冒充局部修改。
展示原画面、编辑遮罩、清除后、新状态合成后。
检查高光和扬尘误选，新内容跟随表面透视与运动，
保留合理反光、遮挡和边缘模糊。
范围正确后，再加网格、擦除轨迹和推拉镜头。
```

## 9. 只让目标慢下来

```text
目标A在指定动作区间慢下来，背景与人物B正常速度。
检查完整素材、去掉A的背景版本，以及目标分离条件。
分别写输出时间到A/B源时间的映射，保持段边界连续。
目标、遮罩、跟踪与影子使用正确的对应时刻。
不要把整个画面慢放，也不要留一个原速A的分身。
补帧失败或素材覆盖不足时，明确指出并给取舍。
```

## 10. 提升丝滑感，别无差别加特效

```text
请把“更丝滑”落实到可检查改动：
主次先后、速度衔接、稳定阅读、整体透视、模糊和遮挡。
同一控件的外框、数字、单位和拖动点共用一个空间平面。
先找具体差异，保留已经成立的部分。
给修改前后同帧与短段预览，再决定是否扩大修改范围。
```

## 11. 定位卡顿或闪帧

```text
问题发生在本镜的这个时间段，请检查前后连续帧和显示时间戳。
先区分源素材静止、时间映射、渲染缓存/采集异常和播放器缓冲。
不要直接整体加速，也不要只因为几帧接近就判定冻结。
报告检查依据、修正点与复查范围，只改有证据的问题。
```

## 12. 对比审片

```text
请生成原片/复刻同步对比，标签写清左右或上下。
最终优先单流对比，网页支持暂停、慢放、逐帧和下载。
对比发生缩放、裁切、原片进度映射时标注。
检查布局、时序、空间关系、合成边缘和必要动作。
不要通过盖上原片来达到一致感。
```

## 13. 保留完整动作的取舍

```text
当前版本动作不完整/加速太明显。
请先找可以删的引导段和尾部停留，保留我要求的全部动作。
再评估轻微统一调速或延长镜头，并说明各方案代价。
本轮观感和动作完整性优先，不机械压回参考时长。
确认后记录源区间、映射和新时长，其他镜头不改。
```

## 14. 合并与交付

```text
先列出各镜头采用的确定版本、文件、顺序、帧数、fps/PTS和时长。
只合并这些版本，不混入调试版。
按要求交MP4、完整MOV、透明动效MOV及横/竖排对比。
说明透明层范围、音轨、参考时间映射和工程是否自包含。
分别报告规格、解码、时间戳、Alpha、视觉和播放检查。
没做的检查明确写未运行，不宣称全部通过。
```

## 一个完整的协作例子

假设你要给“更换产品包装颜色”做一个短演示，可分三轮，而不是发一句“帮我做得高级”：

**第一轮：**提供参考和自己的包装图，让Agent先解释哪部分是素材、哪部分是图形，计划如何建立原状态、如何显示局部变化。此时交关键截图、布局与输入需求。

**第二轮：**补同一机位的原色与新色视频，要求检查运动、光照和边缘一致性。先看局部遮罩与合成关键帧，再加选择框、颜色控件和操作动画。

**第三轮：**对比正常播放与慢放，指出“新包装在转身时漂移”“控件遮住标签”等具体问题，修正后确认版本，再要求导出格式。

这个例子迁移的是分工和检查方法，不暗示仓库提供了自动换包装算法。第一次做，选一个可分离、遮挡少、动作清楚的小段，比一开始叠十种特效更容易成功。
