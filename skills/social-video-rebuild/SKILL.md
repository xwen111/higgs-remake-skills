# Social Video Rebuild

以参考片的结构、视觉关系和节奏为制作依据，用用户素材与代码重建一个可观看、可修改的镜头或成片。重点是把观察变成素材需求、动画状态和验收证据，避免“看起来差不多”的空泛实现。

只完成用户当前授权的范围：拆解、写提示词、制作单镜、局部修改或合并。安装 Skill 不代表自动授权调用付费生成服务、上传用户媒体或发布项目。没有查看过的文件不声称已经看过；不把推测的原片工具链说成已知事实。

## 1. 从项目的真实状态接手

开始时确认：参考片和源素材能否访问、当前要处理的镜头、已确认版本、用户本轮指出的问题、画幅/时长/格式要求。已有上下文足够时先推进，不让用户重讲完整项目。

有工程就先读现有说明与关键文件，沿用可用结构和参数。先列当前确定版，避免误用旧输出。没有工程时，检查可用运行环境、图像处理与视频工具，先渲染一小段验证；不要声称用户只安装这个 Skill 就已经获得完整工具链。

读取媒体实际规格：宽高、显示比例、帧数、帧率或时间戳、时长、音轨、像素格式和是否有 Alpha。标称 fps 不一定代表恒定帧率；扩展名也不能证明透明通道。

## 2. 将参考拆成可以实现的镜头合同

先确定目标段的起止，而不是直接把整条片子复刻。先找动作转折和图形状态，再细看关键帧；镜头复杂时提高局部抽样密度，不要求全片一律每帧截图。

为这一镜写清：

| 项目 | 要记录的内容 |
|---|---|
| 内容 | 主体、环境、动作、因果变化、必须保留的结果 |
| 摄影 | 景别、机位、推拉/横移/跟随、速度与焦点 |
| 排版 | 标题/正文/控件的相对位置、层级、换行与出现顺序 |
| 空间 | 前后遮挡、透视、接触阴影、物体附着或屏幕贴附 |
| 时间 | 进入、稳定、操作、变化、结果、退出的关键点 |
| 输入 | 每个状态所需的图/视频、干净背景、独立元素 |
| 验收 | 哪些帧比较布局，哪些区间检查连续动作 |

把“观察到的事实、实现推断、自己的方案”分开。字体未核实写视觉匹配；无法确定曲线或角度时先给初始估计，再通过对比调节。

拆解与 HTML 查看页的详细结构见 [references/reference-breakdown.md](references/reference-breakdown.md)。用户只要拆解时，到这里交出可用结果即可，不擅自开始整片制作。

## 3. 先准备适合加工的素材，再动手合成

把每一项变化分配给最合适的工序：

- 连续自然动作、环境运镜、复杂照明、毛发等内容变化，优先在素材中准备。
- 精确文案、数字、选框、参数条、网格与解释图形，优先由代码绘制。
- 人物移动/缩放、贴纸替换、局部调速，需要单独评估分离、跟踪与背景条件。

让生成提示词交代时长目标、动作顺序、机位/运镜、速度和光照；同时说明不生成后期 UI。纯环境图、角色图、真正视频首帧可以是不同资产。

准备状态变体、高清主体、干净背景或时间映射时，阅读 [references/assets-and-time.md](references/assets-and-time.md)。先比较不同状态是否真正对齐；不要把三条各自生成的视频直接整帧切换，当成局部编辑。

缺少输入时先做独立可推进的排版或图形，不用模糊填边、强行加速、放大低清主体掩盖素材问题。若采用近似方案，明确说明效果边界。

## 4. 建立镜头的实现结构

在可用工程内分开管理：素材来源、时间映射、跟踪/遮罩数据、视觉参数、图形绘制、合成与输出。无需为了小任务引入庞大框架，但不能把所有版本、路径和参数混在一个不可追踪的函数里。

动画由明确的帧或输出时间决定。源视频时间与动画时间分开；不要用真实墙上时钟驱动导出。随机纹理需要固定种子。渲染顺序不同不应改变结果。

先做稳定关键状态，确认布局、透视与合成，再连接进入/退出。文字更换后重新适配长度，不能简单沿用原标题宽度。优先共享坐标系统，避免背景缩放了而控件跟踪坐标没缩放。

关于时间、投影、文字、合成与渲染的实现交接，阅读 [references/remotion-implementation.md](references/remotion-implementation.md)。该文件提供结构与伪代码，不是已经安装好依赖的完整程序。

## 5. 遇到具体效果，选择对应路径

| 效果 | 先验证什么 | 主要实现思路 |
|---|---|---|
| 窗口收拢 | 层级、转轴、先后与标题露出点 | 独立图形窗口、整体投影/形变、错峰退出 |
| 图层展开 | 元素能否分开、空位如何补 | 透明元素+干净背景，分层变换与边框解释 |
| 运动表面换字 | 状态对齐、有效编辑区域 | 跟踪/透视、局部清除、贴合新状态，保留光影与遮挡 |
| 局部慢动作 | 目标与背景能否独立 | 分离目标、双时间映射、同步遮罩与阴影 |
| 光照控件 | 素材是否有真实照明变化 | 先对齐光照节点，再同步球体、光点、亮度和时钟 |
| 年代切换 | 机位/构图差异能否比较 | 状态素材、时间尺、边界过渡与一致文案 |
| 脸部/物体线框 | 跟踪锚点是否稳定 | 局部跟踪、平滑与遮挡处理，线框跟随有效特征 |

先输出中间证据：原图、遮罩、干净背景、独立元素、替换后关键帧。抠图、高清重建和补背景是不同工作；没有通用自动分层保证。

常见故障与修正顺序见 [references/motion-and-review.md](references/motion-and-review.md)。不要因一个效果有难度就跳过后续仍能完成的图形/排版工作，也不要反复渲染来替代诊断。

## 6. 审片：把问题定位到时间和对象

需要同步对比时，明确原片与复刻的左右/上下排列。最终优先合成单流对比，减少双播放器缓冲差异；对比发生裁切、缩放或时间映射时标注。

每轮修改写成：当前版本、时间点/帧号、对象、差异、修改目标、复查位置。一次修改影响有限范围，已确认的其他镜头不覆盖。不要以原片截图或视频覆盖新画面来制造一致感；参考媒体仅用于明确标注的对比。

“像”“顺”“没有闪”必须有相应观察。解码成功不能证明合成自然；帧率高不能证明动作连续；Alpha 存在不能证明它只包含约定图形层。

## 7. 时长取舍与版本确认

原片动作、自己的素材和目标时长不一致时，先检查无用引导段和尾部停留，再考虑轻微调速或延长。保留用户要求的动作，不能剪掉跑动后仍声称完整保留。用户确认动作优先后，不再静默硬压回原时长。

确定版记录版本、源素材区间、时间映射、帧数与 fps/PTS、已知限制和文件路径。若要合并，先列清单，确认顺序不混入旧版本；保留原生时间结构，统一 fps 造成的重采样需要说明。

## 8. 交付与证据

按请求交可播放文件；完整 MOV 与透明动效 MOV 分清范围。透明层不烙棋盘格，窗口内部如果有意不透明也写明。原始视频、参考片与源素材不因交付工程而自动获得公开授权。

交付检查和报告模板见 [references/delivery-and-validation.md](references/delivery-and-validation.md)。根据实际执行报告：规格、完整解码、时间戳、Alpha、关键帧目视、对比和浏览器播放；没运行的项目写未运行，不用漂亮结论代替证据。

合并与确定版的像素一致性仅验证合并没有改变已确认画面，不能表述成与原片逐像素一致。不同有损编码之间不能强求字节相同。
