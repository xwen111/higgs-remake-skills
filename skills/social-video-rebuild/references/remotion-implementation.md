# 代码动效的实现交接

当任务进入 Remotion 或其他代码视频工程时读取。本仓库提供方法，不附运行依赖；具体 API 和命令应查当前工具的官方文档，不假定用户装有某个版本。

## 1. 选择最小但可维护的结构

一个复杂镜头可按以下职责拆分，不要求固定文件名：

```text
scene/config       画幅、布局、文案、颜色、关键时刻
scene/asset-map    输入路径、源区间、已确认素材版本
scene/time-map     输出时间 → 不同源素材时间
scene/tracking     跟踪点、投影、配准、遮罩数据
scene/ui           文字、控件、网格与光标绘制
scene/composite    素材和图形的层序与混合
scene/render       输出参数和可重复渲染入口
```

小镜头可以合并文件，但同一个数字不要散落在不同函数。改变一个布局参数时，相关边框、内容与跟踪坐标应一起更新。

## 2. 明确时间输入，避免隐藏状态

核心绘制可概括为 `frame = render(output_time, config, assets)`。暂停、跳帧、倒序查看或多进程渲染时，同一时间应得到同样的状态。

不要依赖前一帧“累加了多少”，不要用当前真实时间驱动粒子或控件。纹理/噪声需要固定种子。使用缓存时把时间、素材、参数和版本纳入缓存键，防止一次修改仍读到旧贴纸或旧数值。

跨帧状态不可避免时，先生成确定的数据再渲染，而不是渲染过程中临时追踪一个只在顺序播放下成立的结果。

## 3. 时间映射与图形动画分离

背景、主体、效果分别有时间输入，最终在输出时间上合成。下面是概念伪代码，不是可以直接运行的 Remotion 工程：

```text
t = output_frame / output_fps
bg = sample(background, background_time(t))
subject = sample(subject_video, subject_time(t))
mask = sample(subject_mask, subject_time(t))
scene = composite(bg, subject, mask, tracking_at(t))
ui = draw_controls(t, parameter_state(t))
result = composite(scene, ui)
```

如果跟踪来自源视频，`tracking_at` 可能也要经相应源时间映射，不能总拿输出帧号直接查源跟踪数组。

## 4. 关键状态与曲线

先确定稳定关键帧：位置、缩放、透明度、旋转、模糊、遮罩和数值。再决定各状态之间如何过渡。

每两个点都重新套一次 ease-in/ease-out，可能让运动在每个关键点都减速，形成一顿一顿的感觉。需要连续速度时，选择能保持速度衔接的插值，或用统一曲线控制整段；需要明确停顿时才让速度降到零。

参数约束：透明度保持有效范围，擦除半径非负，图层尺度避免穿过零，透视分母不得跨过相机平面。局部变形先看内容是否可读，再增加曲率。

给窗口群设计统一的总体进度与各层延迟，优于为每层随机写动画。交接时让旧元素退出与新元素进入有明确因果关系，避免每个对象都只完成自己的独立表演。

## 5. 坐标系统与投影

区分素材像素、画面坐标、控件局部坐标和屏幕坐标。对视频缩放/裁切后，把跟踪点应用同样变换。只缩图片不缩标记，是常见漂移原因。

一个透视控件建议先在局部平面里画完整：圆环、数字、单位、标签、手柄，然后整体投影。2D缩放能改变外观宽高，但不能自动得到近大远小和正确的内部透视关系。

贴表面的图形可用平面投影作起点；表面弯曲、明显视差或遮挡变化时，需要更细的网格/分区/遮罩。不要把一组四角点映射宣传成解决所有3D表面的通用办法。

## 6. 素材与图形层序

先建立层表，例如：背景→主体阴影→主体→附着图形→前景尘土/遮挡→解释UI→标题。具体顺序由画面决定。

如果数字需要被尘土挡住，它不能直接画在所有层最上面。若控件是屏幕HUD，则可能应在场景遮挡之上。不要把“UI”和“物体上的纹理”混成同一种层序。

透明元素边缘要在浅、深两种底色上检查。投影、缩放、模糊与颜色预乘方式不一致，可能出现矩形边或暗边。先确认 Alpha 与RGB含义，再决定合成和插值方式。

## 7. 排版与数值稳定

文案变了就重排，不把旧截图盖在新字下面。文字容器的最大宽度、对齐锚点和换行应明确。数值变化预留最大位宽，避免1与8宽度不同造成整条控件晃动。

若采用系统字体，说明不同设备可能有字形差异；若需要稳定字形，选择可分发字体并确认许可，不复制用户系统字体文件到公开仓库。

## 8. 渲染与性能

先渲染短段检查输出路径、字体、素材读取和透明设置。把昂贵的配准、遮罩、跟踪与补帧尽量放到可缓存的预处理，不每一输出帧重复做整段分析。

快速运动的多次时间采样可以帮助表现模糊，但增加计算量，也可能把应该锐利的数字或过渡边界一起糊掉。按元素决定采样层次，而不是对所有东西一刀切。

复杂 Canvas/WebGL 工程若出现截图采集异常，检查原始像素与浏览器采集是否一致；必要时采用对应工程支持的原生像素导出再编码。不能以此推断每个工程都应该换渲染器。

隔离帧重渲染可以检查缓存或状态污染。GPU边缘的一点差异与可见闪帧不是同一个问题，应结合差异范围、Alpha、编码和肉眼观感判断。

## 9. 实现交付给下一位 Agent

写清入口、配置位置、素材映射、输出方式、已确认版本和限制。不要让下一位只拿到一个大脚本和“运行一下就行”。保留必要说明，但不要把本机凭据、绝对路径或第三方媒体顺手复制到公开资料。
