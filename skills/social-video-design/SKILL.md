# Social Video Design

把用户说的“像 Higgsfield、有高级感、动画丝滑”转成可以画、生成、编程和验收的方案。核心不是收集特效，而是安排观众看懂一件事：**对象原来怎样，做了什么操作，哪里变了，为什么这个结果值得看。**

本 Skill 提供创作与评审方法，不代表 Higgsfield 官方规范。没有原工程时，不能认定它的制作软件、字体文件、缓动参数或产品能力。参考视频没有实际读取时，明确把输出称为设计建议。

## 1. 接手任务：先确定现在要解决什么

从对话和现有文件识别当前阶段，不要求用户重新填写已说明的信息：

| 用户正在做什么 | 本轮应给什么 |
|---|---|
| “学一下这条片子” | 观察、设计解释、可迁移的方法，附关键时间点 |
| “给我的产品做一个类似的” | 主张、视觉方向、可制作的镜头方案和素材需求 |
| “这段不够高级” | 按具体对象与时间定位问题，给修改方向 |
| “给我生成提示词” | 根据已选构图、动作、机位和后期需求写提示词 |
| “开始制作” | 将方案交接为图层、状态、时间和验收点，衔接可用制作工具 |

先提取六个变量：受众、一个主要功能、自己的品牌与角色、可用素材、画幅与时长、希望观众下一步做什么。探索阶段允许暂定，注明假设；只有会改变方案的大缺口才提问。

不因正在学习某个品牌就默认照搬字标、品牌色、人物或配乐。用户要求复刻具体排版时，可以对齐视觉关系；需要换成自己的内容时，保留信息职责，重新适配长度与构图。

## 2. 将抽象卖点改写成画面事件

在安排镜头之前，写一句能拍出来的主张。不要停留在“强大、智能、高效、革命性”。

| 抽象描述 | 可见关系 | 可以配的解释图形 |
|---|---|---|
| 可编辑 | 指定一个对象，改变它，其余画面保持稳定 | 选框、编辑区域、前后状态 |
| 可控速度 | 目标动作放慢，参照对象继续正常运动 | 速度控件、数值和运动对照 |
| 可分层 | 一个完整场景展开成不同空间层 | 平面边框、层标签、坐标轴 |
| 可调光照 | 同一场景从日光过渡到黄昏/夜晚 | 光源位置、亮度与时间 |
| 能理解时代 | 相近构图中的环境按年代变化 | 年份标尺、变化边界 |

为每个镜头明确：**观众此刻只需要看懂什么？哪一处变化是证据？**若产品并不真的具备演示的能力，标为概念片或制作实验，不把虚构 UI 包装成产品真实工作流。

## 3. 组织整条片子：有入口、有演示、有结果

先用一个最容易比较的案例教会观看方式，再增加变化。可选两种组织，按用户内容决定：

- 同一个场景连续改不同参数：适合证明一致性和可控性。
- 多个场景展示同一种操作：适合说明适用范围。每个新场景要增加新信息，而不只是换一个漂亮背景。

镜头序列可以采用“吸引注意→命名主张→清楚演示→扩展案例→结果→下一步入口”。这是一种设计选择，不是固定模板或增长公式。不要强制某个总时长，先看动作覆盖、阅读量与用户平台。

开场给少量真正不同的方案，每个写清第一眼画面、正在发生的事件、留下的兴趣点，以及如何接回产品。不要只改标题措辞就当成不同创意。

安排节奏时分开控制：镜头换得多快、每镜新增多少信息、同屏有几个关注对象。三项一起加速通常难读。快速换案例时保留稳定的标题或比较框架；引入新论点时减少旧元素。

## 4. 视觉系统：先让稳定关键帧成立

在动起来之前，先设计一个观众能看懂的稳定状态。至少交代：

- 主体占哪一块区域，哪里留给标题、解释文字和控件。
- 大标题负责哪句话，小字补什么，参数数值证明什么。
- 文字的对齐、换行、字号关系、字重与背景对比。
- 主背景色、行动色、结果色的职责；优先按用户品牌迁移。
- 控件贴屏幕还是贴场景物体；它的透视和遮挡依据是什么。

不要只把长英文缩到能塞下。优先压缩文案、改换行、扩大安全区域，再考虑减字号。面向手机观看时，按最终缩小后的画面检查，不因桌面全屏能读就判通过。

需要布局与空间细节时，阅读 [references/visual-grammar.md](references/visual-grammar.md)。其中包含文字、色彩、图形语义、透视和动效交接的检查方法。

## 5. 把“丝滑”转成明确动作

为每个重要元素写四个阶段：进入、稳定、变化、退出。它们不一定等长，也不一定全部存在；保留能解释当前任务的阶段。

描述运动要包含起止状态、先后关系、路径、加减速、遮挡和交接对象。例如：

> 主窗口先向后倾，前侧两个窗口随后错峰收走；文字在前景腾空后出现，留出稳定阅读段，再由下一个场景接走。

比“做一个很高级的窗口动画”更能指导制作。给出的角度、时长、透明度等数值应标为新方案的初始值，不能冒充从原工程读取的参数。

质感问题先检查层级、时序和速度，再考虑加模糊、发光或弹簧。控件的文字与框线共用空间关系；不要只把外圈压扁，留下正面文字。需要“微微透视”时，优先少量变化并保持可读，而不是大角度旋转。

## 6. 为后期留好素材条件

方案阶段就问：这个主体后面要不要放大、移走、换颜色、单独变速？

- 要放大：准备独立高清主体，不把低清远景当成无限可放大的素材。
- 要移走：准备干净背景，考虑原投影和主体空位。
- 要换状态：从同一基础素材派生，维持机位和运动。
- 要局部变速：提前考虑背景版本与遮挡分离。
- 要特写开场：另外设计对应首帧，不默认全景环境图能完成。

自然动作、运镜和复杂真实照明，可由视频模型生成；精确文案、参数、标记和线框留给代码。这里的分工按工具能力调整，不承诺任何模型能严格按秒执行。

需要具体镜头构型和素材交接时，阅读 [references/shot-blueprints.md](references/shot-blueprints.md)。它包含窗口、分层、局部编辑、速度、光照、时代等可迁移案例；按当前任务选择，不要求一条片子全用。

## 7. 交给制作 Agent 的输出格式

按任务规模给必要产物。复杂镜头推荐用下列结构，不为一句文案修改强制生成整套方案：

```text
镜头目的：观众要看懂的一个关系
时长与画幅：用户约束；动作与阅读能否容纳
参考观察：实际看到的布局、动作、关键时刻
自己的方案：主体、环境、品牌和文案如何替换
画面层级：背景/主体/解释图形/文字/前景遮挡
状态顺序：进入 → 稳定 → 操作与变化 → 结果 → 退出
素材需求：每份输入的用途、清晰度、比例与一致性
动效交接：路径、先后、速度、空间关系和下一镜连接
验收点：关键状态能否看懂，哪里需要同帧/连续帧对比
未确认项：字体来源、原片软件、产品能力或不可见素材
```

如果用户要提示词，给图片与视频两类，不把后期控件塞进视频提示词；如果用户要评审，输出“时间/对象→差异→影响→建议”，不要只评价“再高级一些”。

## 8. 最终设计检查

在方案交付前，检查：去掉说明小字还能否理解主要变化；每个图形是否有含义；同屏主次是否清楚；结果是否有稳定展示；换成用户内容后文案长度是否仍合适；素材条件是否支持后期。

若画面看起来高级但观众不知道在展示什么，先减少装饰并重排证据。若设计成立但难以生成或合成，优先改机位、主体数量、遮挡和素材准备方式，再增加特效。
